# WOW NOW · AI Architecture + ระบบความรู้ · ฉบับอ้างอิง v001 (14 พ.ย. 2026)
กรณีตัวอย่างแรก: BIB / icoone

## 1. หลักออกแบบ AI 6 ข้อ
1. ข้อมูลชุดเดียว · AI รู้งานจริงเพราะเห็นข้อมูลครบ ไม่ใช่เพราะโมเดลเก่ง
2. งานที่ AI ทำแทนเป็นรายการที่กำหนดไว้ (ออกเอกสาร · ส่ง LINE · นัดหมาย · ย้ายขั้นลีด) ผูกสิทธิ์ตามบทบาท + ปุ่มทำทันที/ทบทวนก่อน
3. ตัวเลขมาจากข้อมูลในระบบและบอกที่มา · ไม่มีข้อมูลให้ถามกลับ
4. ข้อมูลและความจำ AI แยกขาดรายบริษัท
5. คนแก้ → กดยืนยัน → เป็นความรู้ canon
6. โมเดลข้างหลังเปลี่ยนได้ · คุมค่าใช้จ่าย AI ต่อบริษัท

## 2. คำศัพท์
| คำ | ความหมาย |
|---|---|
| System Prompt / Project Instructions | คำสั่งพื้นฐานที่ตั้งครั้งเดียว AI อ่านทุกครั้ง |
| Skill / แม่แบบงาน | ขั้นตอนทำงานเฉพาะงาน เรียกใช้เมื่อเกี่ยวข้อง |
| Canon | ความรู้ฉบับที่อนุมัติแล้ว ใช้อ้างอิงได้ |
| Semantic Layer / คลังความหมาย | คำในบริษัทหมายถึงอะไร (เช่น "เดโม" "ลีดร้อน") |
| Single Source of Truth | ข้อมูลลูกค้าชุดเดียวที่ทุกคนและ AI ใช้ |

## 3. ส่วนที่ AI ใช้
| ส่วน | คืออะไร | ตัวอย่าง | เก็บใน Supabase |
|---|---|---|---|
| 1 ความรู้ | อะไรจริง | การ์ดโปรแกรม · หลักฐาน · คำกล่าวอ้าง (เขียว/เหลือง/แดง) · pain · ประเภทลูกค้า · ภาพ | ตารางการ์ด + ดัชนีค้นหาความหมาย (pgvector) + แท็ก |
| 2 วิธีเลือกความรู้ | หยิบการ์ดไหน | ตาม pain + ประเภทลูกค้า + เมนูคลินิก · งานสาธารณะใช้เฉพาะการ์ดเขียว | ตารางกติกาการค้น |
| 3 เสียงแบรนด์ | พูดยังไง | ชั้น BIB/icoone + ชั้นคลินิก | ตารางคำสั่ง แยกชั้น |
| 4 ขั้นตอนคิด | ทำตามลำดับไหน | ถามกลุ่มเป้าหมาย → ดึงการ์ด → ร่าง 3 แบบ → ตรวจคำกล่าวอ้าง → แนะนำภาพ → คลินิกยืนยัน | ตารางแม่แบบงาน |
| 5 เคสตัวอย่าง (เพิ่ม 14 พ.ย.) | ข้อมูลเข้า → ไนน์คิดยังไง → ผลออก | เคสคุณแพร · เคสเดอะมาโลจิก้า · ข้อสอบชุดที่ 1 | ตารางเคส |
| 6 ข้อมูลลูกค้า + ผลลัพธ์ | เปลี่ยนตลอด | เมนู · สัดส่วนลูกค้า · ผลโพสต์ | ตารางลูกค้า (แยกขาดรายคลินิก) |
ความรู้ = "อะไรจริง" แก้เมื่อมีหลักฐานใหม่ · คำสั่ง = "ทำยังไง" แก้เมื่ออยากให้ AI ทำงานต่าง · แยกเก็บ แยกแก้ มีเลขรุ่นของตัวเอง

## 4. System Prompt อยู่ตรงไหนในแพลตฟอร์ม
อยู่หลังบ้าน · ประกอบใหม่ทุกครั้งที่มีคนถาม
| ชั้น | เนื้อหา | ใครแก้ |
|---|---|---|
| 1 คำสั่งหลักของแบรนด์ | ตัวตน · เสียงแบรนด์ · กติกา อย./FDA · ตอบจากการ์ดเท่านั้น | ไนน์ / ผู้ดูแลที่มอบสิทธิ์ |
| 2 ข้อมูลบริษัท/คลินิก | ชื่อ · กลุ่ม A–H · เมนู · ภาษา | ผู้ดูแลคลินิกนั้น |
| 3 บทบาทผู้ใช้ | ขาย · เทราปิสต์ · เจ้าของ · ทีม BIB → ทำ/เห็นอะไรได้ | ตั้งครั้งเดียว |
| 4 แม่แบบงาน | ออกข้อเสนอ · ร่างข้อความนัด · ทำโพสต์ | ทีม BIB |
| 5 ข้อมูลที่ดึงตอนถาม | การ์ดที่เกี่ยวข้อง + ข้อมูลลูกค้าล่าสุด | ระบบดึงเอง |
- Supabase Edge Function ประกอบชั้น 1–5 แล้วส่งให้โมเดล · ของที่ออกนอกบริษัทขึ้นจอ "ทบทวนก่อนส่ง"
- หน้าผู้ดูแล "คำสั่ง AI": ดู · แก้ · เทียบรุ่น · กดเปิดใช้รุ่นใหม่ โดยไม่ต้องแก้โค้ด

## 5. การ์ดความรู้
- 1 การ์ด = 1 เรื่องที่ตรวจกับต้นฉบับได้ และหยิบไปใช้เดี่ยวได้
- ฟิลด์: id · ประเภท · ข้อความสั้น 1–5 ประโยค · ข้อความต้นฉบับ · ที่มา+หน้า · สี · ใช้กับเครื่องมือไหน · ใช้กับกลุ่มไหน · ภายใน/สาธารณะ · วันที่ตรวจ · คำพ้อง · เลขรุ่น
- ตัวอย่าง:
```
id: K-PRE-003
เรื่อง: ที่ปรึกษามักถูกจ้างช้า ราว 3 เดือนก่อนเปิด เพื่อหาคน ทั้งที่ควรเข้ามาตั้งแต่ช่วงออกแบบ
ที่มา: ประสบการณ์ไนน์ 20 ปี · ระดับ: เหลือง
ใช้กับเครื่องมือ: แผน 90 วัน · แผนการตลาด
ใช้กับกลุ่ม: เจ้าของ pre-opening · ทีมองค์กร
ภายใน/สาธารณะ: สาธารณะ
ตรวจล่าสุด: 14 พ.ย. 2026
```
- เครื่องมือแต่ละตัวประกอบ: คู่มือขั้นตอนของตัวเอง + การ์ดที่ติดป้าย + เคส 1–2 เคส + กติกาเสียง + ข้อมูลผู้ใช้ → ทุกข้อสรุปต้องอ้างการ์ด ข้อที่อ้างไม่ได้ติดธง "ความเห็น"

## 6. วงจรป้อนกลับเข้าคลังความรู้
| ขั้น | ทำอะไร | ใคร/อะไร |
|---|---|---|
| เก็บ | บันทึกการใช้เครื่อง · ผลโพสต์ · บันทึกการคุยฝ่ายขาย · ส่วนที่คนแก้คำตอบ AI · คำถามที่ AI ตอบไม่ได้ · คำตอบควิซผู้เรียน (ยินยอมแล้ว) | เทราปิสต์ · ฝ่ายขาย · ผู้เรียน · ระบบ |
| สรุปเป็นข้อเสนอ | สัปดาห์ละครั้ง เสนอการ์ดใหม่/แก้ใบเดิม พร้อมหลักฐาน | Claude ตามรอบเวลา |
| ตรวจ | การแพทย์ → แพทย์ · โปรโตคอล → ทีมเทรน · ราคา/ขาย → หัวหน้าฝ่ายขาย · เสียงแบรนด์และวิธีคิด → ไนน์ | คน |
| ส่งกลับ | อนุมัติ → การ์ดรุ่นใหม่ · เก็บรุ่นเก่า | ระบบ |
เคสเดียวยังไม่ใช่ความรู้ (≥10 ครั้ง → insight สีเหลือง · มีงานวิจัย → สีเขียว) · คำถามที่ AI ตอบไม่ได้ = ข้อมูลมีค่าที่สุด
